# 床タグ検出と効果音

床に貼った AprilTag (**tag16h5**, ID 0 / 1 / 2) をスマートフォンのカメラで
検出し、**そのスマートフォン自身から**対応する効果音を鳴らします。

## 構成

```
[スマートフォン]
  カメラ映像
    ↓
  js-aruco2 で tag16h5 を検出（端末内で完結）
    ↓
  ID が確定した瞬間に効果音を再生
                                   ┌──────────────────────────────┐
  ページの取得だけ ── https ──────▶ │ ロボットPC (trolley_api)      │
                                   │  8000 http : 操作画面 + API   │
                                   │  8443 https: 検出ページ       │
                                   └──────────────────────────────┘
```

検出も再生もスマートフォンの中で完結します。ロボットPCは**ページを配るだけ**で、
走行中に通信は発生しません。ROSのトピックにも流していません。

## なぜポートを分けているのか

カメラ (`getUserMedia`) は **secure context でしか使えません**。
`http://192.168.x.x:8000/` から開いたページではカメラが開けないため、
検出ページは HTTPS で配る必要があります。

一方で操作画面 (`/controller/`) は `ws://` で WebSocket を張るので、
HTTPS にすると mixed content になって接続できません
（`docs/phone_controller.md` と `api_server.py` のコメント参照）。

同じポートでは両立しないので、`trolley_api` のプロセスの中に
HTTPS の待ち受けをもう1本だけ足しています。実装は
`trolley_api/detector_server.py` です。

## 必要なPythonパッケージ

`docs/phone_controller.md` に書かれているものに加えて、自己署名証明書の
発行に `cryptography` が要ります。ROS 2 の環境には大抵すでに入っています。

```bash
pip install "fastapi" "uvicorn[standard]" "cryptography"
```

## 起動

操作画面と同じ launch に含まれています。追加の操作は要りません。

```bash
cd ros2_ws
colcon build
source install/setup.bash
ros2 launch trolley_bringup trolley_phone.launch.py
```

起動すると、開くべきURLと証明書の指紋がログに出ます。

```
[INFO] [trolley_api.detector]: 床タグ検出ページ: https://192.168.11.6:8443/
[INFO] [trolley_api.detector]: 証明書 SHA-256: A3:C1:59:...
```

### 設置作業のとき

タグの貼り付け位置決め、カメラの画角合わせ、音量確認だけをしたい場合は、
走行スタックを立ち上げずに検出ページだけを起動できます。

```bash
ros2 run trolley_api detector_server
```

### launch引数

| 引数 | 既定値 | 説明 |
| --- | --- | --- |
| `with_detector` | `true` | 検出ページ（HTTPS）を配信するか |
| `detector_port` | `8443` | 検出ページの待ち受けポート |

```bash
ros2 launch trolley_bringup trolley_phone.launch.py with_detector:=false
```

証明書は `~/.local/state/trolley_api/certs` に置かれます
（`--cert-dir` か `TROLLEY_DETECTOR_CERT_DIR` で変更可）。
`install/` の下ではないので `colcon build` で消えません。

## スマートフォン側の手順

1. ロボットと同じWi-Fiに接続します。
2. ブラウザで `https://<ロボットPCのIP>:8443/` を開きます。
3. 「安全ではない」警告が出ます。証明書が自己署名だからです。
   Safari なら「詳細を表示」→「この Web サイトを閲覧」。
   表示される指紋が起動ログの SHA-256 と一致していることを確認してください。
4. **端末の消音（マナー）スイッチを解除し、音量を上げます。**
   消音中はブラウザの音も鳴りません。
5. 「開始」を押します。カメラの許可を求められたら許可します。
6. 「音テスト」で ID 0 → 1 → 2 の音が順に鳴ることを確認します。

ホーム画面に追加しておくと、ブラウザのUIが隠れて誤タップが減ります。

IPアドレスが変わると証明書が作り直され、警告の承認もやり直しになります。
会場では固定IPかDHCP予約にしておいてください。

## 効果音の鳴り方

**タグが確定した瞬間に1回だけ**鳴ります。

```
      タグが見える ──────────────▶ 見えない
frames  1   2   3   4   5  ...
                ↑
            ここで1回鳴る（confirm_frames = 3）

                        見失ってから hold_ms (400ms) 経過
                            ↓
                        ここで再武装。次に見えたらまた鳴る
```

- 1〜2フレームだけ検出が途切れても鳴り直しません。
- タグの上で止まっていても連打されません。
- ID ごとに独立して判定します。0 と 1 が同時に見えれば両方鳴ります。
- ID 0 / 1 / 2 以外は、検出されても音は鳴りません（画面には出ます）。

## 誤検出への備え

tag16h5 は情報ビットが16bitしかなく、誤検出しやすい辞書です。
誤って鳴った効果音は観客に確実に気づかれるので、3段で弾いています。

1. `max_hamming_distance = 0` — 完全一致のみ許可
2. `confirm_frames = 3` — 3フレーム連続で見えたものだけ確定
3. `min_tag_area_ratio` — 小さすぎる四角形は無視

3つめは効果音のために追加したものです。偽陽性は遠景のノイズに出やすく、
たいてい非常に小さくなります。床にカメラを向けた固定設置ならタグの
見かけの大きさはほぼ一定なので、実測に合わせて詰めてよい値です。

## タグの印刷

検証環境に印刷用のページがあります。

```
C:\Users\keisu\programming\smartphone_apriltag\web\tags.html
```

貼り付けの目安:

- **黒枠の外形で10cm以上**。カメラが床の1.5m幅を写すなら、これで
  解析画像（幅640px）上で40px程度になります。小さすぎると検出できません。
- **周囲に白い余白**を外形の 1/6 以上とってください。黒枠の外側が
  白でないと、タグの輪郭が四角形として拾われません。
- つや消しの紙に印刷してください。光沢紙は照明が映り込んで黒枠が飛びます。

## 効果音を差し替える

いまは音源ファイルを持たず、Web Audio で合成しています。
`web_detector/se.js` の `VOICES` に ID ごとの音が定義してあります。

```js
const VOICES = {
  0: { label: 'ID 0 — 上昇', notes: [ /* 周波数と長さ */ ] },
  ...
};
```

音源ファイルに差し替える場合は、`se.js` の `play()` を
`AudioBufferSourceNode` を鳴らす実装に置き換えてください。
呼び出し側（`app.js`）は変更不要です。差し替え方は `se.js` の
`play()` のコメントに書いてあります。

## パラメータ

検出の挙動は `web_detector/app.js` 冒頭の `CFG` にまとまっています。
値は検証環境（`smartphone_apriltag`）の実写ベンチで決めたものです。

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `max_hamming_distance` | `0` | 許容ハミング距離。上げると誤検出が増える |
| `confirm_frames` | `3` | 確定に必要な連続フレーム数 |
| `hold_ms` | `400` | 見失ってから破棄するまでの時間 [ms] |
| `process_width` | `640` | 解析画像の幅 [px]。小さいほど速く不正確 |
| `threshold_kernels` | `[3, 7, 14]` | 二値化カーネル半径。**検出率にいちばん効く** |
| `threshold_offset` | `7` | 局所平均から何階調暗ければ前景とみなすか |
| `rescan_ms` | `200` | 追従中に全カーネル掃引を挟む間隔 [ms] |
| `min_tag_area_ratio` | `0.002` | 効果音を鳴らすタグの面積の下限。0で無効 |

`threshold_kernels` を変えるときは `web_detector/detector.js` の冒頭を
読んでください。この値がなぜ複数必要なのか（単一のカーネルでは
ある距離レンジしかカバーできない）が書いてあります。実写140枚での検出率は
`[2]` で20.0%、`[10]` で98.6%、`[3, 7, 14]` で100%でした。

## トラブルシューティング

| 症状 | 確認すること |
| --- | --- |
| ページが開けない | URLが `https://` になっているか。ポートは8443か |
| 「カメラを使えません」と出る | `http://` で開いていないか。カメラは HTTPS 必須 |
| カメラが拒否される | 設定 → Safari → カメラ を「確認」または「許可」に |
| 画面は動くが音が鳴らない | 消音スイッチ。「音 停止中」バッジが出ていないか。「音テスト」で確認 |
| タグを写しても枠が出ない | 照明。`threshold_kernels` を広げる。タグが小さすぎないか |
| 橙の破線は出るが緑にならない | 確定前。`confirm_frames` に届いていない。ブレか小ささが原因 |
| 緑枠は出るが鳴らない | ID 0/1/2 以外ではないか。画面の「直前の効果音」を見る |
| 鳴りっぱなし・連打する | `hold_ms` が短すぎないか。検出が明滅していないか |
| 起動ログにURLが出ない | `cryptography` が入っているか。ログにエラーが出ていないはず |

検出ページが立ち上がらなくても、操作画面と走行には影響しません。
証明書の発行やページの配信に失敗した場合は、理由をログに出して
検出ページだけを諦めるようにしてあります。

## 既存構成への影響

- `trolley_api` の `console_scripts` の `api_server` が
  `api_server:main` から `run_server:main` へ変わりました。
  以前のエントリポイントは待ち受け先が決め打ちで、launch が渡していた
  `--host` / `--port` を読んでいませんでした（`api_port` を変えても
  8000 のままでした）。この修正で launch 引数が実際に効きます。
- `api_server.py` の `main()` は削除しました。同じ罠を繰り返さないためです。
  `uvicorn trolley_api.api_server:app` での起動は従来どおり使えます。
- 操作画面 (`/controller/`)・API・走行系の挙動は変えていません。
